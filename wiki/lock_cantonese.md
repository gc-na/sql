# SQL 鎖定 (LOCK) 命令詳解

## 概述
SQL 鎖定（LOCK）命令用於管理數據庫中的併發控制，確保在多個使用者同時訪問數據時數據的完整性和一致性。透過鎖定，數據庫能夠防止數據衝突和不一致的情況。

## 文件說明
### 目的
鎖定命令的主要目的是控制對共享資源的訪問，確保在進行讀取或寫入操作時不會發生數據競爭。鎖定可以根據需求選擇性地應用於行、頁或整個表。

### 用法
在 SQL 中，鎖定通常與事務處理結合使用。當一個事務開始時，系統會自動為相關的數據加鎖，並在事務結束時釋放鎖定。您可以手動使用 `LOCK TABLE` 或 `SELECT ... FOR UPDATE` 來控制鎖定行為。

### 詳細說明
1. **共享鎖 (Shared Lock)**: 允許多個事務同時讀取數據，但不允許任何事務修改該數據。
2. **排他鎖 (Exclusive Lock)**: 允許某一事務對數據進行讀取和修改，並阻止其他事務訪問這些數據。
3. **意向鎖 (Intent Lock)**: 一種用於表示某個事務希望在特定層級上獲取排他鎖或共享鎖的鎖定機制。

這些鎖定可以是自動的，也可以是手動的，並且通常與 `BEGIN TRANSACTION` 和 `COMMIT` 結合使用。

## 示例
### 基本用法
1. 鎖定整個表：
   ```sql
   LOCK TABLE my_table IN EXCLUSIVE MODE;
   ```

2. 在選擇時鎖定行：
   ```sql
   SELECT * FROM my_table WHERE id = 1 FOR UPDATE;
   ```

3. 使用共享鎖進行讀取：
   ```sql
   SELECT * FROM my_table WHERE id = 1 LOCK IN SHARE MODE;
   ```

## 解釋
### 常見問題
- **死鎖 (Deadlock)**: 當兩個或多個事務互相等待對方釋放鎖定時，會導致死鎖。這通常需要數據庫管理系統（DBMS）自動檢測和解決。
- **鎖定超時**: 如果一個事務在獲取鎖定時等待超過預設的時間，則會產生鎖定超時錯誤。
- **性能影響**: 不當的鎖定會影響數據庫性能，特別是在高併發的環境中，因此需要謹慎設計鎖定策略。

## 一句總結
SQL 鎖定命令用於控制數據庫中的併發訪問，確保數據完整性及一致性。
