# SQL CALL 명령어: 저장 프로시저 호출 방법

## 개요
SQL의 `CALL` 명령어는 데이터베이스에서 저장 프로시저를 호출하는 데 사용됩니다. 이 명령어를 통해 복잡한 비즈니스 로직을 데이터베이스 내부에서 효율적으로 실행할 수 있습니다.

## 문서화
### 목적
`CALL` 명령어는 데이터베이스에 미리 정의된 저장 프로시저를 실행하여 특정 작업을 수행하도록 합니다. 저장 프로시저는 데이터베이스 서버에 저장된 SQL 코드 블록으로, 재사용이 가능하고 성능 최적화에 유리합니다.

### 사용법
`CALL` 명령어의 기본 구문은 다음과 같습니다:

```sql
CALL 프로시저이름(매개변수1, 매개변수2, ...);
```

- `프로시저이름`: 호출할 저장 프로시저의 이름입니다.
- `매개변수`: 저장 프로시저에 전달할 입력 값입니다. 매개변수는 선택 사항이며, 프로시저 정의에 따라 다를 수 있습니다.

### 세부 정보
- `CALL` 명령어는 MySQL, PostgreSQL, Oracle 등 다양한 SQL 데이터베이스에서 사용됩니다.
- 저장 프로시저가 반환 값을 가질 경우, `OUT` 매개변수를 통해 값을 반환 받을 수 있습니다.
- 트랜잭션 관리와 같은 복합적인 작업을 처리할 때 유용합니다.

## 예제
1. 매개변수가 없는 저장 프로시저 호출:
    ```sql
    CALL myProcedure();
    ```

2. 매개변수가 있는 저장 프로시저 호출:
    ```sql
    CALL calculateTotal(10, 20);
    ```

3. OUT 매개변수를 사용하는 저장 프로시저 호출:
    ```sql
    CALL getEmployeeCount(@totalCount);
    SELECT @totalCount;
    ```

## 설명
- **공통 함정**: 저장 프로시저가 존재하지 않거나 이름이 잘못된 경우, SQL 오류가 발생합니다. 프로시저 이름과 매개변수를 정확히 확인해야 합니다.
- **매개변수의 타입**: 매개변수의 데이터 타입이 맞지 않으면 오류가 발생할 수 있으므로, 정의된 프로시저의 매개변수 타입을 사전에 확인해야 합니다.
- **보안**: 저장 프로시저는 권한 관리에 유리하지만, 잘못된 사용 시 보안 취약점을 초래할 수 있습니다. 따라서 권한 설정에 주의해야 합니다.

## 한 줄 요약
SQL의 `CALL` 명령어는 저장 프로시저를 호출하여 데이터베이스 내에서 재사용 가능한 SQL 작업을 수행하는 기능입니다.
