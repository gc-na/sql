# SQL의 LOCK: 데이터베이스에서의 동시성 제어

## 개요
SQL에서 "LOCK" 명령은 데이터베이스의 동시성 제어를 위해 사용되며, 여러 트랜잭션이 동일한 데이터에 접근할 때 데이터의 일관성을 유지하는 데 도움을 줍니다.

## 문서화

### 목적
LOCK 명령은 데이터의 무결성을 보장하기 위해 특정 자원에 대한 접근을 제한합니다. 트랜잭션이 실행되는 동안 다른 트랜잭션이 동일한 자원에 접근하지 못하도록 하여 데이터 손실 및 충돌을 방지합니다.

### 사용법
LOCK 명령은 데이터베이스에서 특정 행(row) 또는 테이블(table)을 잠그는 데 사용됩니다. 이 명령은 데이터베이스의 종류에 따라 다르게 구현될 수 있으며, 주로 다음과 같은 두 가지 유형의 잠금을 제공합니다:
- **공유 잠금 (Shared Lock)**: 여러 트랜잭션이 동시에 데이터를 읽을 수 있지만, 수정은 불가능합니다.
- **배타적 잠금 (Exclusive Lock)**: 해당 데이터를 수정할 수 있는 유일한 트랜잭션이 되며, 다른 모든 트랜잭션은 해당 데이터에 접근할 수 없습니다.

### 세부사항
LOCK 명령의 기본 구문은 다음과 같습니다:

```sql
LOCK TABLE table_name IN lock_mode;
```

- `table_name`: 잠글 테이블의 이름.
- `lock_mode`: 사용할 잠금의 유형(예: SHARE, EXCLUSIVE).

각 데이터베이스 시스템마다 LOCK 명령의 세부 사항이 다를 수 있으므로, 사용하는 데이터베이스의 문서를 참조하는 것이 좋습니다.

## 예제

1. **공유 잠금 예제**
```sql
LOCK TABLE employees IN SHARE MODE;
```
이 예제에서는 `employees` 테이블에 대해 공유 잠금을 설정하여 다른 트랜잭션이 이 테이블의 데이터를 읽을 수 있지만 수정할 수는 없도록 합니다.

2. **배타적 잠금 예제**
```sql
LOCK TABLE employees IN EXCLUSIVE MODE;
```
이 예제에서는 `employees` 테이블에 대해 배타적 잠금을 설정하여 이 테이블의 데이터를 수정할 수 있는 유일한 트랜잭션으로 만듭니다.

## 설명
LOCK을 사용할 때 주의해야 할 몇 가지 사항이 있습니다:

- **교착 상태 (Deadlock)**: 두 개 이상의 트랜잭션이 서로 상대방의 잠금을 기다릴 때 발생합니다. 이를 피하기 위해 잠금 순서를 일관되게 유지해야 합니다.
- **성능 저하**: 불필요한 잠금은 성능 저하를 초래할 수 있으므로, 필요한 경우에만 잠금을 사용하는 것이 좋습니다.
- **잠금 유지 시간**: 가능한 한 짧게 유지하여 다른 트랜잭션이 대기하는 시간을 최소화해야 합니다.

## 한 줄 요약
SQL의 LOCK 명령은 데이터 무결성을 보장하기 위해 특정 자원에 대한 접근을 제한하여 동시성 제어를 수행하는 데 사용됩니다.
